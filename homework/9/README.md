# 用搜尋法解五個經典問題

搜尋法的共同心法：**把問題畫成一張「狀態圖」，然後在圖上找一條從起點到目標的路。**

```
起點狀態 --[動作]--> 新狀態 --[動作]--> ... --> 目標狀態
```

只要先講清楚三件事，程式就完成大半：

1. **狀態是什麼？**（座標？誰在哪一岸？皇后放在哪？）
2. **有哪些動作？**（上下左右？農夫過河？在下一列放一顆皇后？）
3. **怎麼判斷到達目標？**

剩下的差別只有一個：**下一個要展開哪個狀態**——這就是 DFS、BFS、A* 的差別。


## 策略總覽

| 策略 | 候選狀態放在哪 | 展開順序 | 保證最短？ | 適合 |
|---|---|---|---|---|
| DFS | 堆疊 / 遞迴 | 沿一條路走到底，死路再退 | 否 | 只要「找得到」、要列舉全部解 |
| BFS | 佇列 (FIFO) | 一層一層擴散 | 是（每步成本相同時） | 最少步數 |
| A* | 優先佇列 (heap) | 取 f = g + h 最小者 | 是（h 不高估時） | 有「方向感」的尋路 |

三者其實是同一套樣板：`frontier（待展開）＋ visited（來過了）＋ parent（怎麼來的）`，只是 frontier 換了資料結構。

## 1. 老鼠走迷宮（DFS）

**狀態化**

| | |
|---|---|
| 狀態 | 座標 `(y, x)` |
| 動作 | 上、右、下、左各走一步（不能穿牆 `#`） |
| 目標 | 走到 `E` |

**做法**：遞迴 DFS，並維護兩樣東西。

```python
def dfs(y, x):
    visited.add((y, x))
    path.append((y, x))              # 深入 = push
    if (y, x) == goal: return True
    for 四個方向:
        if 不是牆 and 沒走過:
            if dfs(ny, nx): return True
    path.pop()                       # 死路 = pop，這就是「回溯」
    return False
```

- `visited`：避免在迷宮裡繞圈圈、無限遞迴。
- `path`：目前這條路的堆疊，走進去 push、發現死路就 pop 退回。

**特性**：DFS 只保證「找得到就找到」，**不保證最短**，走哪條路取決於方向的試探順序。要最短路請用 BFS 或 A*。

**執行結果**（`*` 是 DFS 找到的路）：

```
找到路徑！長度 = 55 格，共嘗試 67 格

#############
#S**#*******#
#.#*#*#####*#
#.#***#***#*#
#.#####*#*#*#
#*******#***#
#*#######.###
#*#*****#...#
#*#*###*###.#
#***#..*....#
#######*#####
#E******#####
#############
```

可以看到 DFS 繞了很大一圈才到終點，這正是它「不保證最短」的樣子。

## 2. 狼羊甘藍菜過河（BFS）

**狀態化**

| | |
|---|---|
| 狀態 | `(農夫, 狼, 羊, 菜)`，每個是 0（左岸）或 1（右岸），共 2⁴ = 16 種 |
| 起點 / 目標 | `(0,0,0,0)` / `(1,1,1,1)` |
| 動作 | 農夫過河，可獨自過，或帶一件和他同岸的東西 |
| 約束 | 農夫不在場時：狼不能和羊同岸、羊不能和菜同岸（違反的狀態不合法，不展開） |

題目沒有格子，只有抽象的規則；但「狀態＋動作＋目標」的框架照樣通用。

**為什麼用 BFS？** 題目問的是「最少要過幾次河」。BFS 一層一層展開，「第幾層」就是「第幾步」，所以第一次取出目標狀態時，走的一定是最短解。

```python
frontier = deque([起點]);  parent = {起點: ...}      # parent 兼當 visited
while frontier:
    s = frontier.popleft()                            # FIFO：同一層先做完
    if s == 目標: 用 parent 回溯出路徑; return
    for nxt in 合法動作(s):
        if nxt 沒來過 and 合法: parent[nxt] = s; frontier.append(nxt)
```

**執行結果**：最少 **7 次**渡河，BFS 只展開了 10 個狀態（總共 16 個）。

```
0. 出發           狀態 = (0, 0, 0, 0)
1. 農夫帶著羊過河      狀態 = (1, 0, 1, 0)
2. 農夫單獨過河       狀態 = (0, 0, 1, 0)
3. 農夫帶著狼過河      狀態 = (1, 1, 1, 0)
4. 農夫帶著羊過河      狀態 = (0, 1, 0, 0)   ← 關鍵：把羊再載回來
5. 農夫帶著菜過河      狀態 = (1, 1, 0, 1)
6. 農夫單獨過河       狀態 = (0, 1, 0, 1)
7. 農夫帶著羊過河      狀態 = (1, 1, 1, 1)
```

人常在第 4 步（羊載過去又載回來）卡住；BFS 不靠直覺，窮舉就能找到。

## 3. 八皇后（DFS + 剪枝 = 回溯法）

**狀態化**

| | |
|---|---|
| 狀態 | `queens[r] = c`，表示第 r 列的皇后放在第 c 行（一列一顆，已先排除同列衝突） |
| 動作 | 在下一列的 8 個行各試一次 |
| 約束 | 同行不可；兩條對角線不可 |
| 目標 | 放滿 8 列（要找**全部**解） |

衝突判斷（`i` 是前面某一列）：

```python
queens[i] == col                      # 同一行
abs(queens[i] - col) == row - i       # 同一條對角線
```

**剪枝 (pruning) 是重點**：放下去「馬上就被打」的格子，直接不遞迴，整棵子樹都不用看。

```python
def dfs(row):
    if row == N: 記下這組解; return
    for col in range(N):
        if attacked(queens, row, col): continue    # 剪枝
        queens.append(col); dfs(row + 1); queens.pop()   # 回溯
```

**執行結果**

```
共找到 92 組解（理論值 92），剪枝版展開 2,057 個節點
（不剪枝要展開 (8^9-1)/7 = 19,173,961 個節點）

解 1：行號序列 = [0, 4, 7, 5, 2, 6, 1, 3]
Q . . . . . . .
. . . . Q . . .
. . . . . . . Q
. . . . . Q . .
. . Q . . . . .
. . . . . . Q .
. Q . . . . . .
. . . Q . . . .
```

- 剪枝後節點數少了約 **9,300 倍**，答案（92 組）完全一樣。
- 實測對照 N=6：剪枝 153 個節點 vs. 不剪枝 55,987 個節點，解數都是 4。
- 不同 N 的解數：N=4→2、5→10、6→4、7→40、8→92、9→352、10→724。

## 4. NPC 搜尋玩家（A*）

**問題**：遊戲地圖上有牆，NPC 要用最少步數走到玩家身邊。這就是遊戲 AI 的「尋路 (pathfinding)」。

**A* 的想法**：BFS 是對每個方向都一視同仁地擴散；A* 替每個候選格子打分數，優先走「看起來比較接近目標」的。

```
f(n) = g(n) + h(n)
        │       └─ 估計 n 到目標還要多遠（這裡用曼哈頓距離）
        └───────── 起點走到 n 的實際步數
```

- 用 `heapq` 每次取 f 最小者展開。
- **只要 h 不高估真實剩餘距離（admissible），A\* 就保證找到最短路。** 在四方向、每步成本 1 的格子地圖上，曼哈頓距離恰好滿足。
- 特例：h 恆為 0 時，A* 就退化成 BFS（Dijkstra）。

**同一張地圖三種方法實測**（`*` 為 A* 的路徑）：

```
A* 找到路徑：24 步，展開 52 格

###############
#N....#.......#
#*###.#.#####.#
#*#...#.#...#.#
#*#.###.#.#.#.#
#*#.....#.#...#
#*#######.#####
#*********#***#
#.#######*#*#*#
#.#.....#***#P#
#...###...###.#
###############

A*  ： 24 步（最短）  展開  52 格
BFS ： 24 步（最短）  展開  71 格
DFS ： 68 步（不保證）展開  69 格
```

A* 和 BFS 都找到最短的 24 步，但 A* 少展開了約 27% 的格子；DFS 雖然展開得也不多，路卻繞了 68 步。

程式最後還有個小模擬：玩家一直逃，NPC **每回合重新用 A\* 規劃**——這就是遊戲 AI 每一幀在做的事。

## 5. IC 設計中的電路繞線

**問題**：把晶片的一層金屬想成 R×C 的格子。每條 net 要連接兩個接腳，且

- 不同 net 的導線**不能共用同一格**；
- 不能穿牆 (blockage)，也不能穿過別條 net 的接腳。

這是「迷宮尋路」加上「很多條線互相擋路」的版本。因為方法很多，下面分四層說明：

### A. 單一 net：三種格子搜尋法

| 方法 | 本質 | 做法 | 保證最短？ |
|---|---|---|---|
| **Lee** | BFS 水波 | 從起點一圈圈往外擴張，碰到終點後沿 parent 回溯 | 是 |
| **Hadlock** | 0/1 BFS | 往「接近目標」的步成本 0，往「遠離目標」(detour) 成本 1；用 deque（成本 0 放前面、成本 1 放後面） | 是 |
| **A\*** | 啟發式搜尋 | f = g + 曼哈頓距離 | 是 |

Hadlock 為什麼最短：路徑長度 = 曼哈頓距離 + 2×(detour 次數)，所以 **detour 最少 ⇔ 路徑最短**。

在 10×14 的格子、中間有障礙牆的測試中（可走格數 121），三種方法都找到長度 **24** 的最短線路，差別在「要展開多少格才知道答案」：

| 方法 | 展開格數 |
|---|---|
| Lee | 114 |
| Hadlock | 72 |
| A* | 91 |

Lee 幾乎淹過整張圖；Hadlock、A* 有「方向感」所以少走很多冤枉路。（哪個較省取決於地圖形狀，這張圖上 Hadlock 最省。）

### B. 多條 net：逐條繞，順序很重要

最直接的做法：一條一條繞，前面繞好的線變成後面的障礙。問題是**先繞的 net 會把路擋死**。

測試用的 7×7 地圖（`#` 牆、大寫 = 接腳、小寫 = 導線）有 3 條 net，6 種繞線順序的結果：

```
A→B→C：失敗     A→C→B：成功     B→A→C：失敗
B→C→A：失敗     C→A→B：成功     C→B→A：成功
```

同一組 net，只因為順序不同就有一半會失敗。這就是 EDA 工具有 **net ordering**（排序）的原因，但「找出好順序」本身也很難。

### C. Rip-up & Reroute（撕掉重繞）

順序不好時不要放棄：**撕掉擋路的線，讓卡住的 net 先過，再重繞被撕掉的**。

```
net A 繞成功（3 步）
net B 繞成功（11 步）
net C 繞不通 → 撕掉 ['B']            ← C 的理想路線被 B 擋住
net B 繞成功（13 步）                ← B 換一條路重繞
```

```
B b . A a a A
# b . # C c .
. b . . # c c
# b . . . # c
. b . . . c c
. b b b C c B
. . . b b b b
```

總線長 24。

### D. PathFinder（協商式壅塞，negotiated congestion）

現代 FPGA / 繞線器常用的思路：**先允許大家重疊，再靠「漲價」讓大家自己談出不衝突的路。** 每個格子的成本：

```
cost(c) = (1 + 歷史壅塞 hist[c]) × (1 + pf × 目前有幾條線佔用 c)
```

每一輪：每條 net 把自己撕掉，用 Dijkstra 在這組成本下重繞；有格子被多條線共用 → 該格 `hist` 加 1、`pf` 調高，下一輪更貴。

```
第 1 輪：超載格數 = 3     ← 人人都走自己的最短路，互相撞在一起
第 2 輪：超載格數 = 1
第 3 輪：超載格數 = 0     ← 談判完成
```

```
B b b A a a A
# . b # C c c
. . b b # . c
# . . b . # c
. . . b c c c
. . . b C . B
. . . b b b b
```

總線長 24。和 B 的逐條繞不同，PathFinder 不需要事先決定順序。

### 沒有實作、但值得知道的繞線方法

- **線探索法 (line-probe，如 Mikami-Tabuchi)**：不一格一格擴散，而是沿直線「探出去」，用記憶體換速度。
- **多層繞線**：把狀態擴充成 `(layer, y, x)`，換層 (via) 要付額外成本；一層不通時可以「跳到另一層」。
- **多接腳 net / Steiner 樹**：一條 net 連 3 個以上的點時，不是找最短路，而是找最小生成樹／Steiner 樹。
- **通道繞線 (channel routing)**：如 Left-edge 演算法，處理兩排接腳之間的通道。
- **全域繞線 + 細部繞線**：先在粗網格規劃每條線走哪一帶，再在細格子內實際畫線。

## 五題的共同心得

1. **先把問題翻成「狀態、動作、目標」**，搜尋法自然就長出來。
2. **要的答案不同，策略就不同**：只要有解 → DFS；要最少步數 → BFS / A*；要全部的解 → 回溯法（DFS + 剪枝）。
3. **剪枝與啟發函數決定效率**：八皇后剪枝省了 9,000 多倍的節點；A* 比 BFS 少展開約四分之一的格子。
4. **當問題不只一條路時（IC 繞線），單純的最短路不夠**：還要處理路徑互相搶資源（順序、撕掉重繞、協商漲價）。
