## 第 1 章　希爾伯特的問題

### 1.1 背景：1900 年的 23 個問題

- 1900 年，希爾伯特（David Hilbert）在巴黎第二屆國際數學家大會發表《數學問題》演講，提出 23 道最重要的數學問題。
- 其中**第 2 問題《算術公理之相容性》** 對程式領域影響重大；要理解它，須先從「數學中的公理系統」談起。

### 1.2 何謂定理證明

- 文藝復興前期，歐洲從穆斯林手中譯回失落的《幾何原本》。
- 歐洲人發現：整個幾何學可從「點、線、面、圓」等基本定義，加上簡單的公理系統，透過明確的推論法則，一步一步建構出來。
- **透過公理系統建構定理，基本上就是數學家最重要的任務。**
- 隨之而來的問題：能不能把這樣的數學推論**自動化、形式化**？這大致就是希爾伯特第 2 問題想問的事。
- 希爾伯特想要的不是幾何式的描述，而是**從邏輯學開始的描述**；這種描述源自亞里斯多德的三段式論。

**亞里斯多德三段式論（以蘇格拉底為例）**

1. 大前提：人都會死
2. 小前提：蘇格拉底是人
3. 結論：蘇格拉底會死

**改寫成一階邏輯（First-Order Logic）**

1. ∀x People(x) ⇒ Mortal(x)　（只要 x 是人，x 就會死）
2. People(Socrates)
3. Mortal(Socrates)

- **∀** 代表「對於所有」，**∃** 代表「存在」，兩者是一階邏輯的基本符號。
- 一階邏輯是現代數學企圖將古希臘邏輯公理化的嘗試。

### 1.3 用布林邏輯示範公理系統與推論法則

一階邏輯仍偏複雜，改用較簡單的**布林邏輯（Boolean Logic）** 示範。給定：

```
事實：   A, B
規則庫： C => G
         A => E
         B => F
         E&F => H
```

問：能否推論出 H？

**Modus Ponens（肯定前件）推論法則**

```
P
P => Q
-------
Q
```

推論過程：

```
A        B        E&F => H
A => E   B => F   E
-------  -------  F
E        F        -------
                  H
```

- 經由「事實 + 規則庫」，透過 Modus Ponens 可一步一步推論出 H 是對的，這就是布林邏輯的嚴格推論範例。

**推論引擎（inference.py）架構**

| 函數 | 作用 |
|---|---|
| `satisfy(exp, facts)` | 檢查 facts 是否滿足邏輯式 exp（以 `&` 切開逐項檢查） |
| `gen(facts, rules)` | 掃描規則庫，若左式被滿足就把右式新增為事實，並印出推論過程 |
| `inference(facts, rules)` | 反覆呼叫 `gen`，直到沒有新事實產生為止 |
| `load(file)` | 讀入知識庫：含 `=>` 者為規則，其餘為事實 |

- 這是**前向推論**（由已知事實往前推）。

**測試一：test.kb**

```
E&F=>H
A=>E
C=>G
B=>F
A
B
```

- gen 1：由 A、A=>E 推出 E；由 B、B=>F 推出 F。
- gen 2：由 E、F、E&F=>H 推出 H。
- gen 3：沒有新結果，推論完畢。

**測試二：animal.kb（動物世界知識庫）**

- 規則例：`有毛=>哺乳類`、`泌乳=>哺乳類`、`有羽毛=>鳥類`、`會飛&生蛋=>鳥類`、`哺乳類&吃肉=>食肉類`、`有爪&利齒&兩眼前視=>食肉類`、`哺乳類&有蹄=>有蹄類`、`哺乳類&反芻=>偶蹄類`、`哺乳類&吃肉&斑點=>獵豹`、`哺乳類&吃肉&條紋=>老虎`、`有蹄類&長腿&斑點=>長頸鹿`、`有蹄類&條紋=>斑馬`、`鳥類&長腿=>鴕鳥`。
- 已知事實：`會飛`、`生蛋`、`長腿`。
- 推論結果：`會飛&生蛋 → 鳥類`，再由 `鳥類&長腿 → 鴕鳥`。

### 1.4 希爾伯特想要什麼？

- 希爾伯特問的是：**有沒有可能透過形式化推論，讓數學定理以機械化方式自動被證明出來？**
- 更重要的是：這種機械化方式是否能證明**所有**定理（即**完備性**）？
- 上述前向推論法的限制：
  1. 它推不出所有定理。例如推不出**笛摩根定律（De Morgan's laws）**，因為系統只會推出單一的布林變數，而不是邏輯法則。
  2. 但若引入**公理（Axioms）** 搭配 Modus Ponens，就有可能推出這類邏輯法則。例如以下公理系統：
     1. p → (q → p)
     2. (p → (q → r)) → ((p → q) → (p → r))
     3. (¬p → ¬q) → (q → p)
- 進一步的推論法則可參考 **Propositional Calculus（命題演算）**，如 Simple axiom system、Natural deduction system。
- 核心問題：**有沒有方法可以推論出所有為真的邏輯法則，也就是所有的「定理」？**

### 1.5 希爾伯特計劃（Hilbert Program, 1920）

除列入 23 個問題的第 2 題外，希爾伯特於 1920 年提出希爾伯特計劃，企圖為全部數學提供堅實穩固的理論基礎。具體包括：

1. **所有數學的形式化**：所有數學應使用統一的嚴格形式化語言，並按一套嚴格規則使用。
2. **完備性**：必須證明形式化之後，數學裡所有的真命題都可以被證明。
3. **一致性**：必須證明運用這套形式化與規則，不可能推導出矛盾。
4. **保守性**：若某個關於「實際物」的結論用到了「假想物」（如不可數集合）來證明，那麼不用「假想物」依然可以證明同樣的結論。
5. **確定性**：應該有一個算法，來確定每一個形式化的命題是真命題還是假命題。

- 此計畫的核心理念也稱為**希爾伯特綱領**。

### 1.6 結語

- 希爾伯特第 2 問題《算術公理之相容性》，換成電腦的語言就是：**是否能寫一個程式，自動證明所有算術方面的定理？**
- 這個問題後來被**哥德爾、丘奇、圖靈**等人分別用不同手法、在不同領域問過類似的問題，但答案都是**否定的**。

## 第 2 章　哥德爾的定理

### 2.1 希爾伯特第 2 問題的原文陳述

- 1900 年提出 23 個問題後，許多數學家開始試圖解決它們。
- 第 2 問題「算術公理之相容性」的德文陳述譯成英文，重點為：

> 當我們探究一門科學的基礎時，必須建立一套公理系統，確切而完整地描述該科學基本觀念之間的關係。……最重要的是：**證明它們不是矛盾的**，也就是基於它們的一定數量邏輯步驟永遠不會導致矛盾。在幾何學中，可透過構建適當的數域來證明公理相容性；但**算術公理的相容性需要直接方法**。

- 亦即希爾伯特認為算術系統至少要能：
  1. 從公理出發，像《幾何原本》那樣「用定義與公理、透過明確法則證明定理」。
  2. 證明這樣的系統**不會導致矛盾**。

### 2.2 羅素的悖論

- 羅素（Bertrand Russell）、摩爾、弗雷格、維根斯坦、懷特海等人創立**分析哲學**，認為數學是邏輯學的一部分；羅素試圖建立**邏輯主義**數學體系，把整個數學歸納為邏輯學。
- 他與老師懷特海（Whitehead）合寫三卷本《數學原理》（Principia Mathematica），想用嚴謹方式建立數學的邏輯體系。

**羅素集合悖論（Russell's Paradox）**

定義集合 A = { x | x ∉ x }，則 A ∈ A 是否成立？

1. 若 A ∈ A，依定義 A 應不是 A 的成員，即 A ∉ A。
2. 若 A ∉ A，依定義 A 應是 A 的成員，即 A ∈ A。

- 兩種情況都導致矛盾，故這樣的集合定義是**不一致的（inconsistent）**。
- 這個定義既清楚又簡單，形式上完全符合**樸素集合論**的要求；若它會產生矛盾，代表當時整個**集合論**體系都得打掉重建——作為數學最基礎的集合論垮了，整個數學大廈還建得起來嗎？
- 羅素的感嘆：

> 這世界上最令人絕望的事情，莫過於當一棟大廈即將完工之際，卻發現大廈的基礎已然倒塌。

**理髮師悖論（通俗版）**

- 城裡唯一的理髮師立下規定：**只幫那些自己不理髮的人理髮**。請問理髮師該不該為自己理髮？
  - 若他不給自己理髮，依規則他必須幫自己理髮。
  - 若他給自己理髮，依規則他不能幫自己理髮。
- 羅素用文學手法把集合悖論「換個皮」，讓不懂集合符號的人也能體會悖論。

### 2.3 用一階邏輯重建集合論

- 羅素悖論讓集合論垮掉，數學家於是借用**一階邏輯**、以更嚴格的要求重建集合論，即**公理化集合論**。
- **1908 年，策梅洛（Zermelo）** 提出第一個公理化集合論，即**策梅洛集合論**。
  - 缺點：無法構建出序數的集合，而序數是許多集合論研究的根本工具。
  - 其分類公理使用的「明確性」性質，實際意義有歧義（此時一階邏輯概念尚未提出）。
- **1922 年，弗蘭克爾（Fraenkel）與斯科倫（Skolem）** 獨立提議：
  - 將「明確性」定義為「可在一階邏輯中公式化，且原子公式僅包括集合的公式」。
  - 用**替代公理**取代**分類公理**。
  - 在體系中加入**正規公理**（首先由馮諾依曼提出）。
  - 從而得到 **ZFC** 公理體系。

**ZFC 的十條公理（以口語說明）**

| 公理 | 內容 |
|---|---|
| 外延公理 | 若兩集合的元素完全相同，則兩集合相等 |
| 分類公理 | 可從既有集合 A 中，用性質 P(x) 篩出子集合 B |
| 配對公理 | 任兩元素 x、y 可構成只含兩者的集合 |
| 聯集公理 | 對集合 A，存在其所有成員之元素的聯集 |
| 空集公理 | 存在一個不含任何元素的集合 |
| 無窮公理 | 存在包含空集、且對「x ∪ {x}」封閉的集合 N |
| 替代公理 | 若對每個 x 存在唯一的 y 使 P(x,y)，則可將 A 的元素替換成對應的 y 形成集合 B |
| 冪集公理 | 對集合 A，存在其所有子集合構成的冪集 P(A) |
| 正規公理 | 非空集合 A 中存在元素 x，與 A 無共同元素（排除自我循環歸屬） |
| 選擇公理 | 對非空集合族 X，存在選擇函數 f，使每個 A ∈ X 都有 f(A) ∈ A |

- ZFC 逐漸完備化之後，羅素悖論終於被排除在集合論之外。
- 但這就代表希爾伯特夢想中的自動定理推論機可以被實現嗎？

### 2.4 哥德爾完備定理（1929）

- 1929 年，哥德爾（Kurt Gödel）幾乎實現了希爾伯特的夢想，證明了**哥德爾完備定理**：

> 在 ZFC 的一階邏輯系統中，所有《定理》都是可以被證明的。

- 補充：此處的《定理》指的是永遠為真的邏輯式，也就是**恆真式（tautology）**。

**看似可行，實際不然**

- 哥德爾完備定理涵蓋的公理只有 **ZFC 體系的公理**，推論法則則是 **Hilbert System** 裡的推論法則。
- 問題在於：**若在公理系統裡多加點東西，這些推論法則還能推出所有定理嗎？**
- 哥德爾發現：在 ZFC 公理上再加入**整數論的皮亞諾公理（Peano Axioms, PA）**，完備性就無法確保——這就是《哥德爾不完備定理》。

### 2.5 整數論的皮亞諾公理系統

皮亞諾公理用來描述整數的加法與乘法，包含下列一階邏輯陳述：

1. ∀x (0 ≠ S(x))　— 0 不是任何自然數的後繼者
2. ∀x,y (S(x) = S(y) ⇒ x = y)　— 若 x、y 的後繼者相同，則 x、y 相同
3. ∀x (x + 0 = x)　— x + 0 = x
4. ∀x,y (x + S(y) = S(x + y))　— x + (y+1) = (x+y) + 1
5. ∀x (x · 0 = 0)　— x × 0 = 0
6. ∀x,y (x · S(y) = x · y + x)　— x × (y+1) = x×y + x

### 2.6 哥德爾不完備定理（1931）

**定理陳述**

> 若公理化邏輯系統 T 是個包含基本算術（皮亞諾公設）的**一致性**系統，那麼 T 中存在一種語句 s：你無法用 T 證明 s，卻也無法否證 s。

- 以一階邏輯語句表示，即想問以下邏輯式 Q 是否為真：

  ∃s ¬Provable(s) ∧ ¬Provable(¬s)

- 問題是：假如我們可以用邏輯語句表達出 **Provable**（可證明）這個觀念，會不會產生矛盾？這正是證明的核心。

**Q 的真假分析**

- **狀況 1：Q 為真** → 代表存在無法證明的定理，即 Provable 函數沒辦法證明所有定理。
- **狀況 2：Q 為假** → 代表 ¬Q 應為真。那麼 Provable(¬Q) 會傳回什麼？
  - 2.1 Q 是個定理（恆真式），也就是「存在 s 無法被證明」，那麼 Q 不就應該為真嗎？
  - 2.2 Q 不是個定理，也就是存在 s 無法被證明，那麼 Q 不就應該為真嗎？
  - 兩個可能性都產生矛盾，所以狀況 2 不可能發生。
- 因此只能是**狀況 1**：存在無法證明的定理。

### 2.7 完備又不完備？

- 哥德爾既證明《完備定理》又證明《不完備定理》，看似矛盾，但用條件區分就不矛盾：

| 定理 | 條件 | 結論 |
|---|---|---|
| 哥德爾完備定理 | ZFC 的一階邏輯系統 | 所有《定理》都可被證明 |
| 哥德爾不完備定理 | ZFC 的一階邏輯系統**加入皮亞諾公理** | 不是所有《定理》都可被證明 |

- 白話版：
  1. 完備定理：一階邏輯的《集合論》，所有定理都可被證明。
  2. 不完備定理：一階邏輯的《集合論 + 整數論》，有些定理無法被證明。
- 原因：一階邏輯系統沒辦法編碼表示 Provable 這樣的函數；但加入皮亞諾公理之後，哥德爾找到方法把 Provable 等觀念編碼出來，才能建構語句「∃s ¬Provable(s) & ¬Provable(¬s)」。
- 此證明思路與後來《圖靈證明停止問題不可解》相當類似。

### 2.8 結語

- 1929 年哥德爾證明一階邏輯世界一致且完備（完備定理）之後，希爾伯特的自動推論機似乎就快要實現了。
- 1931 年哥德爾又證明加入皮亞諾公理的一階邏輯是不完備的（不完備定理），希爾伯特的自動推論機夢想差不多就算破滅了。

## 第 3 章　丘奇的函數

### 3.1 背景

- 哥德爾提出不完備定理後，希爾伯特的問題基本上得到否定答案：自動定理證明機器無法證明所有數學定理。
- 但這不妨礙人們繼續研究數學。丘奇（Alonzo Church）對一種**函數的代數轉換技巧**特別有興趣，這套技巧稱為 **λ-Calculus（λ 演算）**。

### 3.2 λ-Calculus 的形式語法

- 與一階邏輯相似，都有變數（通常寫成 x, y, z, …）。
- 不同之處：λ-Calculus **不考慮真假值**，是一種純粹的**代換系統**。
- 形式語法只有兩種：

1. (λx.M)　— 匿名函數的定義
2. (M N)　— 函數應用

**代換法則**

| 法則 | 內容 | 說明 |
|---|---|---|
| α-conversion | (λx.M[x]) → (λy.M[y]) | 更改名稱（避免名稱衝突） |
| β-reduction | (λx.M) N → M[x := N] | 參數替換（把 x 換成 N） |

- 這樣一套簡單的代換系統，成為 **Functional Programming（函數式程式設計）** 領域的先驅，而且是不可超越的典範。
- 以下均用 Python 示範 λ-Calculus 的觀念。

### 3.3 IF 系統

```py
TRUE  = lambda t:lambda f:t
FALSE = lambda t:lambda f:f
IF    = lambda c:lambda t:lambda f:c(t)(f)
```

- 執行結果：`IF(TRUE)("YES")("NO")` → YES；`IF(FALSE)("YES")("NO")` → NO。
- 重點：**在完全沒有 true、false、0、1、2… 等基本型態的情況下，硬是定義出 IF / TRUE / FALSE 的概念。**

### 3.4 完整的邏輯系統（Church Booleans）

```py
TRUE  = lambda t:lambda f:t          # λ t f. t
FALSE = lambda t:lambda f:f          # λ t f. f
AND   = lambda p:lambda q:p(q)(p)    # λ p q. p(q)(p)
OR    = lambda p:lambda q:p(p)(q)    # λ p q. p(p)(q)
XOR   = lambda p:lambda q:p(NOT(q))(q)
NOT   = lambda c:c(FALSE)(TRUE)      # cond ? FALSE : TRUE
IF    = lambda c:lambda t:lambda f:c(t)(f)
```

- 另定義驗證工具：
  - `ASSERT(truth)`：回傳 `[✓]`／`[✗]` 訊息。
  - `REFUTE(truth)`：等於 `ASSERT(NOT(truth))`。
  - `TEST(description)(assertion)`：印出測試結果。
- 測試 TRUE、FALSE、AND、OR、XOR、NOT 全部通過。

### 3.5 整數系統（Church Numerals）

**基本算術函數**

| 函數 | 定義 |
|---|---|
| IDENTITY | λx.x |
| SUCCESSOR | λn.λf.λx. f(n(f)(x))（後繼者，即 +1） |
| PREDECESSOR | λn.λf.λx. n(λg.λh. h(g(f)))(λ_.x)(λu.u)（前驅者，即 −1） |
| ADDITION | λm.λn. n(SUCCESSOR)(m) |
| SUBTRACTION | λm.λn. n(PREDECESSOR)(m) |
| MULTIPLICATION | λm.λn.λf. m(n(f)) |
| POWER | λx.λy. y(x) |
| ABS_DIFFERENCE | λx.λy. ADDITION(SUBTRACTION(x)(y))(SUBTRACTION(y)(x)) |

**Church Numerals：用函數表示自然數**

- 0 用 λf.λx. x 表示（即 IDENTITY）。
- 1 = S(0)、2 = S(1)、3 = S(2)、4 = 2×2、5 = S(4)、8 = 2×4、9 = S(8)、10 = 2×5。
- 這樣的做法與**皮亞諾公理**非常類似。

**比較函數**

| 函數 | 定義 |
|---|---|
| IS_ZERO | λn. n(λ_.FALSE)(TRUE) |
| IS_LESS_THAN_EQUAL | λm.λn. IS_ZERO(SUBTRACTION(m)(n)) |
| IS_LESS_THAN | λm.λn. NOT(IS_LESS_THAN_EQUAL(n)(m)) |
| IS_EQUAL | λm.λn. AND(IS_LESS_THAN_EQUAL(m)(n))(IS_LESS_THAN_EQUAL(n)(m)) |
| IS_NOT_EQUAL | λm.λn. OR(NOT(IS_LESS_THAN_EQUAL(m)(n)))(NOT(IS_LESS_THAN_EQUAL(n)(m))) |
| IS_GREATER_THAN_EQUAL | λm.λn. IS_LESS_THAN_EQUAL(n)(m) |
| IS_GREATER_THAN | λm.λn. NOT(IS_LESS_THAN_EQUAL(m)(n)) |
| IS_NULL | λp. p(λx.λy.FALSE) |
| NIL | λx.TRUE（空串列） |

### 3.6 Y-Combinator

- 為了方便**遞迴呼叫**而設計（原文註明「有點神祕，需要另外解釋」）。

```py
# 另一種定義方式 Y = lambda g:g(lambda:Y(g))
Y = lambda f:\
  (lambda x:f(lambda y:x(x)(y)))\
  (lambda x:f(lambda y:x(x)(y)))
```

- 推導關係：令 g = λx. f(λy. x(x)(y))，則 Y(g) = g(g) = g(g)(y) = …

### 3.7 LIST 結構

- 學過 LISP 的人對 **CONS / CAR / CDR** 印象深刻；它們就是 **PAIR / HEAD / TAIL** 的意義。

```py
CONS = lambda x:lambda y:lambda f:f(x)(y)  # 將 x, y 形成配對 PAIR(x, y)
CAR  = lambda p:p(TRUE)                    # 取得配對的頭部 x（HEAD）
CDR  = lambda p:p(FALSE)                   # 取得配對的尾部 y（TAIL）
```

**range 與 map**

- `RANGE(m)(n)`：以 Y-Combinator 遞迴，從 m 逐一 CONS 到 n，最後接 NIL。
- `MAP(x)(g)`：以 Y-Combinator 遞迴走訪串列，對每個元素套用 g 後重新 CONS；遇到 NIL 則停止。

```
RANGE = λm.λn. Y(λf.λm. IF(IS_EQUAL(m)(n))
                   (λ_. CONS(m)(NIL))
                   (λ_. CONS(m)(f(SUCCESSOR(m)))))
                 (NIL)(m)

MAP   = λx.λg. Y(λf.λx. IF(IS_NULL(x))
                   (λ_. x)
                   (λ_. CONS(g(CAR(x)))(f(CDR(x)))))
                 (NIL)(x)
```

### 3.8 驗證與範例

- 以 ASSERT 逐一驗證：IDENTITY、SUCCESSOR、PREDECESSOR、ADDITION、SUBTRACTION、MULTIPLICATION、POWER、ABS_DIFFERENCE、IS_ZERO、IS_LESS_THAN、IS_LESS_THAN_EQUAL、IS_EQUAL、IS_NOT_EQUAL、IS_GREATER_THAN_EQUAL、IS_GREATER_THAN、IS_NULL、CAR、CDR、CONS、RANGE、MAP。
- 完整版 `lambdaCalculus.py` 執行結果：上述 27 項全部 `[✓]`。

**自訂較大函數**

```py
# 階層 FACTORIAL(n) = n!
FACTORIAL = Y(lambda f:lambda n:IF(IS_ZERO(n))
  (lambda _:SUCCESSOR(n))                        # 0! = 1
  (lambda _:MULTIPLICATION(n)(f(PREDECESSOR(n))))# n! = n × (n-1)!
  (NIL))

# 費氏數列 FIBONACCI(n)
FIBONACCI = Y(lambda f:lambda n:
  IF(IS_LESS_THAN_EQUAL(n)(SUCCESSOR(IDENTITY)))  # n <= 1
  (lambda _:n)
  (lambda _:ADDITION(f(PREDECESSOR(n)))
                   (f(PREDECESSOR(PREDECESSOR(n))))))
```

- 測試結果：`5! = 120`、`FIBONACCI(10) = 55`，皆通過。

### 3.9 結語：丘奇 1936 年的不可解問題

- 在那個連電腦都還沒有的年代，丘奇竟能發明一套只有函數、沒有任何基本型態（bool / integer / float / struct…）的程式語言，且今日仍可用 Python、JavaScript、LISP 實作出來。
- 更厲害的是，丘奇在 1936 年論文中證明了 λ-Calculus 上的一個不可解問題：

> **THEOREM XIX.** There is no recursive function of two formulas A and B, whose value is 2 or 1 according as A conv B or not.

- 也就是說：**你無法寫出一個函數，能正確判定是否能透過 α-conversion + β-reduction 把 A 函數轉換成 B 函數。**
- 換句話說：**判斷兩個函數是否具有相同功能，是任何程式都做不到的。**

**為何直覺寫法行不通**

```py
def fequal(A, B):
    a = A()
    b = B()
    return a == b
```

- 問題：若 A()、B() 當中有一個不會停，`fequal` 就會當掉。
- 即使採用作業系統的時間中斷技術，強制取回控制權，也無法分辨該函數是「執行太久」還是「真的不會停」，因此無法取得執行結果來比較。

## 第 4 章　圖靈的機器

### 4.1 歷史背景

- 丘奇（Alonzo Church）發表 **λ-Calculus（λ 演算）** 後不久，圖靈（Alan Turing）於 1936 年開始研究機器，成果成為 **圖靈機（Turing Machine）**，是資訊科學的重要基礎。
- 丘奇是圖靈的博士指導教授，也是 **有限狀態機** 發明人 Kleene 的指導教授；Kleene 對 λ-Calculus 的設計貢獻良多，該形式系統由師生二人共同完成。

### 4.2 有限狀態機（Finite State Machine, FSM）

- 歷史上 1956 年才被正式提出，比圖靈機晚 20 年，但結構比圖靈機簡單，是理解圖靈機的踏腳石。
- 範例：辨識二進位字串中是否含**偶數個 0**；圖中 S1 既是起始狀態（被箭號指向），也是結束狀態（雙圈）。

**作為「接受器」的數學定義：**

1. Σ：輸入字母表（符號的非空有限集合）
2. S：狀態的非空有限集合
3. s₀：初始狀態，為 S 的元素
4. δ：狀態轉移函數，δ : S × Σ → S
5. F：最終狀態集合，為 S 的子集

**作為「轉換器」時**，需再加入：

6. ω：輸出函數，ω : S × Σ → Γ（Γ 為輸出字母表）

**實作重點（finiteStateMachine.py）**

- 以 `actionMap` 記錄「狀態,輸入符號 → 下一狀態」，不到 20 行即完成。
- `accept(s)`：從 start 出發逐字元轉移；查不到轉移即回傳 False；最後判斷是否落在 finals。
- 偶數個 0 判斷機的轉移：`s1,0→s2`、`s1,1→s1`、`s2,0→s1`、`s2,1→s2`，起始與接受狀態皆為 s1。
- 測試結果：`010` → True、`101` → False、`10100` → False、`1010010` → True。

### 4.3 圖靈機（Turing Machine）

- 直觀理解：**「加上了磁帶的有限狀態機」**。
- 數學上是七元有序組 **(Q, Σ, Γ, δ, q₀, q_accept, q_reject)**，Q、Σ、Γ 皆為有限集合：

1. Q：非空有限狀態集合
2. Σ：非空有限**輸入字母表**，不含空白符 □
3. Γ：非空有限**磁帶字母表**，且 Σ ⊂ Γ；空白字元 □ ∈ Γ − Σ，是唯一允許出現無限次的字元
4. δ : Q × Γ → Q × Γ × {L, R, −}：轉移函數；L、R 表示讀寫頭左移、右移，− 表示不移動
5. q₀ ∈ Q：起始狀態
6. q_accept ∈ Q：接受狀態
7. q_reject ∈ Q：拒絕狀態，且 q_reject ≠ q_accept

**範例：辨識 aⁿbⁿcⁿ 的圖靈機**

- 轉移規則寫法 `'0,a':'1,_,R'` 表示：狀態 0 遇到 a 轉到狀態 1，寫入 `_`，然後向右移動。
- 策略：把 a 換成 `_` 並向右掃描，依序把 b 換成 x、c 換成 x，再向左回到開頭，循環處理。
- 執行結果：空字串、`abc`、`aabbcc` 接受；`ab`、`abtt`、`aabbc` 拒絕。

**模擬器（turingMachine.py）重點**

- 只需約 35 行：`tape = list(tape + '________')` 補空白格。
- 迴圈中讀取 `tape[i]`、查 actionMap、改寫該格、依 L／R／− 移動讀寫頭。
- 狀態進入 accepts 回傳 True、進入 rejects 回傳 False；查不到動作則回傳 False。

### 4.4 停止問題不可判定

- 圖靈證明：**停止問題（Halting Problem）** 無法用圖靈機解決。
- 定義函數 `isHalt(code, data)`：判斷 `code(data)` 是否會停止；會停輸出 1，不會停輸出 0。

**反證法（對角線式自我指涉）**

```py
def U(code):
    if isHalt(code, code) == 1:
        while True: pass   # 若判斷「會停」，就故意不停
    else:
        exit()             # 若判斷「不會停」，就立刻停止
```

- 若 `isHalt(U, U)` 回傳 1 → U(U) 進入無窮迴圈，實際不會停 → 判斷錯誤。
- 若 `isHalt(U, U)` 回傳 0 → U(U) 立刻停止，實際會停 → 判斷錯誤。
- 兩種情況都矛盾，故 isHalt 不可能 100% 正確。

**常見誤解：直接執行就能判斷？**

```py
def halt(f, input):
    f(input)
    return True
```

- 問題：若 `f(input)` 不會停，`halt` 也跟著當掉，無法回傳結果。
- 即使跑很久（如 f2(1000) 需 1000⁴ 步）也只代表「很久才停」，無法區分「執行太久」與「真的不會停」。
- 即使用作業系統的時間中斷技術強制取回控制權，仍然無法判定。

**推理依據**

- 此問題與「羅素的理髮師問題」同類，都會導致矛盾，因此依矛盾證法可推得：圖靈機或現代電腦都無法正確解答。
- 原文引《韓非子・難一》「矛與盾」故事（吾楯之堅，物莫能陷；吾矛之利，於物無不陷）作為類比。
- 現代電腦能力基本上只相當於**記憶空間有限的圖靈機**；因此圖靈機無法解決的問題，現代電腦也無法解決。
- 反之，若能證明「擁有無限記憶體的現代電腦」無法解決某問題，也就證明了圖靈機無法解決該問題。

### 4.5 結語

- 圖靈對停止問題不可判定的論述，與丘奇論述「兩個 λ-Calculus 函數無法互相轉換」非常類似。

## 第 5 章　喬姆斯基的語法

### 5.1 生成語法（Generative Grammar）

- 喬姆斯基（Noam Chomsky）是語言學大師、生成語法的創始人，被稱為現代語言學之父。
- 1957 年《文法結構》出版，標誌 **轉換-生成文法（Transformational-generative grammar, TG）** 誕生；研究人類為什麼會說話、如何理解新的句子。
- 理論演進：1957《文法結構》與 1965《文法理論要略》合稱「**標準理論**」→「**擴展的標準理論**」→「**修正的擴展的標準理論**」。

### 5.2 BNF（Backus–Naur Form）

- 與喬姆斯基同期，電腦領域也開始研究語法；BNF 由 Fortran 創建者 John Backus 與 Peter Naur 提出，用來描述程式語言語法。
- Backus 首次在 **ALGOL 58** 實作 BNF；Naur 在 **ALGOL 60** 進一步發展並簡化符號，稱其為 Backus Normal Form。
- 後來 Knuth 主張應稱 **Backus–Naur Form**，因為它不算是一種正規形式（Normal form）。
- 語言學與電腦兩個領域的語法觀念幾乎同時發展，且互相影響。

### 5.3 用語法生成語言

**範例：貓狗世界的英文語法**

```
S  => NP VP
NP => D N
VP => V NP
N  => "dog" | "cat"
V  => "eat" | "chase"
D  => "a" | "the"
```

**grammar.py 的生成機制**

1. 取得所有規則的左式（A => B 中的 A），起始符號前後補空白。
2. 在目前的展開式中尋找尚未展開的左式。
3. 隨機從對應的右式集合挑一個取代左式，並印出目前結果。
4. 若整串已全為小寫（非終端項目），代表生成完畢，回傳結果。
5. 每次結果不同，是因為使用了隨機選擇。

**與其他系統的共通性**

- 此機制與《有限狀態機的展開》、《邏輯推理系統的展開》非常相像。
- 共同流程：找到待展開的對象（左式）→ 呼叫右式的動作；差別只在各系統的右式動作不同。

### 5.4 喬姆斯基階層（Chomsky Hierarchy）

喬姆斯基有系統地將生成語法分為 0、1、2、3 四型，分別對應四種機器：

| 文法 | 語言 | 機器 | 生成規則 | 範例 |
|---|---|---|---|---|
| 0 型 | Recursive Enumerable（遞歸可枚舉） | 圖靈機 | α → β | — |
| 1 型 | Context Sensitive（上下文相關） | 線性有界圖靈機 | αAβ → αγβ | aⁿbⁿcⁿ |
| 2 型 | Context Free（上下文無關） | 下推自動機 | A → α | aⁿbⁿ |
| 3 型 | Regular Language（正規語言） | 有限狀態機 | A → a ｜ aB | aⁿbᵐ |

**為何有限狀態機對應 A → a ｜ aB？**

- `A → aB`：在 A 狀態碰到字母 a 後，轉移到 B 狀態。
- `A → a`：在 A 狀態碰到字母 a 後，進入結束狀態。
- 這種語法對應的就是**正規表達式（Regular Expression）** 所能表達的語言。

**為何 αAβ → αγβ 是「上下文相關」？**

- 規則利用 A 前後的 α 與 β 抓住前後文，可依據前後文決定是否觸發規則展開。
- 這種根據前後文展開的特性，就稱為**上下文相關語言（Context Sensitive Language）**。

### 5.5 3 型：正規語言（Regular Language）

- 目標語言 aⁿbᵐ，規則皆為 3 型生成規則，故為 regular grammar：

```
S => A
A => a A | B
B => b B | b
```

- 實作用字典表示，將 `"a A"` 重複三次是為了把該情況的機率增大三倍。
- 生成結果例：`a a a a b b b`（先產生若干 a，再產生若干 b），也可能只產生 `b`。

### 5.6 2 型：上下文無關語言（Context Free）

- 經典案例 **aⁿbⁿ**（n 個 a 後面接 n 個 b），**無法用第 3 型的 regular 語法生成**。

```
S => a S b | a b
```

- 生成結果例：`a a a a b b b b`、`a a a a a a b b b b b b`。
- 特徵：a 與 b 的數量被同一條遞迴規則綁定，同時增長。

### 5.7 1 型：上下文相關語言（Context Sensitive）

- 經典案例 **aⁿbⁿcⁿ**（n 個 a、n 個 b、n 個 c），**無法用第 2 型的 Context Free 語法生成**。

```
S => a B C | a S B C
C B => C Z
C Z => W Z
W Z => W C
W C => B C
a B => a b
b B => b b
b C => b c
c C => c c
```

- 關鍵技巧：`CB → CZ → WZ → WC → BC` 這一連串規則的作用是**交換 C 和 B 的順序**。
- 後四條規則 `aB→ab`、`bB→bb`、`bC→bc`、`cC→cc` 負責把小寫字母「換出來」。
- `S` 的右式重複三次同為 `a S B C`，是為了增大該情況的機率為三倍。
- 生成結果例：`a b c`、`a a a b b b c c c`。

### 5.8 0 型：遞歸可枚舉語言（Recursive Enumerable）

- 0 型語法基本上對應**圖靈機**的能力。
- **邱奇-圖靈猜想（Church-Turing Thesis）**：

> 任何在算法上可計算的問題，同樣可由圖靈機計算。

- 意即 λ-Calculus 這種使用遞迴方式的程式能力，基本上和圖靈機一樣。
- 延伸：任何使用遞迴方式的程式語言能力都一樣，任何通用計算機的能力也都和圖靈機一樣。

### 5.9 結語

- 這並不表示 λ-Calculus 或圖靈機能計算任何函數、辨識任何語言。
- 丘奇證明：兩個 λ-Calculus 是否相等，是**不可解問題**。
- 圖靈證明：**停止問題**也是不可解問題。
- 所以有些語言是沒辦法用電腦或程式正確辨識的。

## 第 6 章　庫克的證明

### 6.1 非確定型圖靈機（Nondeterministic Turing Machine, NTM）

- 圖靈機的一個重要貢獻，是提出非確定型圖靈機的概念；此想法對後來的計算複雜度與 NP-Complete 觀念非常重要。
- 與確定型圖靈機的差別：計算的每一時刻，根據當前狀態與讀寫頭讀到的符號，機器存在**多種**狀態轉移方案，機器任意選擇其中一種繼續運作，直到停機。
- 狀態轉移函數：

  δ : Q × Γ → 2^(Q × Γ × {L,R})

  其中 Q 是狀態集合、Γ 是磁帶字母表、L／R 表示讀寫頭左右移動；2^A 表示集合 A 的冪集，2^A = { S ｜ S ⊆ A }。

**直觀理解**

- 可想像成高度平行的圖靈機：每個分叉點的所有可能性都同時跑下去。
- 正式說法：M 在輸入串 ω 上的計算過程可表示為一棵**樹**，不同分支對應每一步計算的不同可能性。

**接受與拒絕的規定**

- 只要有任意一個分支進入接受狀態，則稱 M 接受 ω。
- 只要有任意一個分支進入拒絕狀態，則稱 M 拒絕 ω。
- 某些分支可能永遠無法停機；但只要有一個分支能進入接受或拒絕狀態，就說 M 在輸入 ω 上可停機。
- M 必須是**無矛盾**的：不能有某分支接受 ω 而同時另一個分支拒絕 ω，這種有矛盾的非確定型圖靈機是不合法的。

**與預言機（Oracle Machine）的關係**

- 理論上，非確定型圖靈機與預言機的執行時間相當。
- 因此若要判定一個問題是否為 NP，可看是否能在多項式時間內**檢查某個解答是否符合該問題的條件**；可以的話，該問題就屬於 NP。

### 6.2 P 與 NP

- **NP** = Nondeterministic Polynomial time：非確定型圖靈機可在**多項式時間**內解決的問題。
- **P** = Polynomial time：確定型圖靈機可在多項式時間內解決的問題。
- **P = NP 問題**：自 1972 年庫克（Stephen Cook）提出後一直未被解決，而且很可能今後也沒有人能解決。

### 6.3 NP-Complete

- 庫克不只提出問題，還證明了 **NP-Complete** 是一組「相互之間可以轉換後解決」的問題，並因此獲得 1982 年圖靈獎。
- 這些問題被綁在一起：只要其中一個能在多項式時間解決，其他問題也都會變成 P 的問題。
- 能把這一大群問題綁在一起的關鍵，就是 **Reduction（歸約）**。

### 6.4 Reduction（歸約）

- 定義：將問題 A 轉成問題 B 的輸入形式，交由問題 B 的算法 b() 解決，再把結果轉回問題 A 的解答形式。

```py
def a(ia):
    ib = a2b(ia)  # 將 A 問題的輸入 ia 轉為 B 問題的輸入 ib
    ob = b(ib)    # 用 b() 去解決 B 問題
    oa = b2a(ob)  # 再將 B 的輸出 ob 轉回 A 問題的輸出 oa
    return oa
```

- 換言之，若 b() 可以解決 B 問題，就能寫出 a() 來解決 A 問題。

**範例：用整數規劃解 n 皇后問題**

- **整數規劃**：在限制條件下找某函數的最大值（或最小值），且解答必須是整數，不可有小數部分。
- **n-queens（n 皇后問題）**：依西洋棋皇后「垂直、水平、斜角移動」的攻擊規則，將 n 個皇后排在棋盤上且互不攻擊；最常見的 n 為 8，即**八皇后問題**。
- 表面與整數規劃無關，但可透過巧妙轉換，用整數規劃求解。
- 以 `mip` 套件求解 8 皇后（queen8.py）的建模方式：
  - 決策變數 x(i, j) 為 BINARY，代表該格是否放皇后。
  - 每個 row 只能有一個皇后（Σ x[i][j] = 1）。
  - 每個 column 只能有一個皇后（Σ x[i][j] = 1）。
  - 每條 `\` 斜角線最多一個皇后（≤ 1）。
  - 每條 `/` 斜角線最多一個皇后（≤ 1）。
  - 呼叫 `queens.optimize()` 求解，`num_solutions` 有值時印出棋盤。
- 結果：CBC MILP Solver 在約 0.30 秒內求出 8 皇后的一組解。
- 這就是**歸約（Reduction）** 的威力。

### 6.5 SAT 問題

- **SAT 問題**：布林式是否能被滿足的問題（命題邏輯公式的可滿足性）。
- 例：`(x or y) and (x or not z)`
  - (x, y, z) = (0, 1, 1) → False
  - (x, y, z) = (0, 1, 0) → True，故該式可被滿足。
- 暴力法：對 n 個變數枚舉所有 2ⁿ 種輸入；只要有任何一組輸出 1（True）即可滿足，全部為 0 則不可滿足。
- 程式以遞迴 `satisfy()` 逐層嘗試 0 與 1，找到即回傳該組 values，否則回傳 None。
- 執行例：
  - `(x or y) and (not x or not z) and (x) and (y)` 在 (1, 1, 0) 被滿足。
  - `(x) and (not x) and (not y) and (not z)` 無論如何都無法滿足。

**為何暴力法不可行**

- SAT 定義清楚、暴力法也不難寫，但變數 n 很大時會非常慢，慢到完全無法接受。
- 若 n = 1024，需檢查 2¹⁰²⁴ 種組合，此數字大到難以想像，實際執行 100 年、甚至 100 億年都未必出得來；n = 1 萬時更不可能。
- 但反過來，若**指定好每個變數是 0 或 1**，就能很快算出該指定值的輸出是 0 或 1。
- NP-Complete 的問題幾乎都和 SAT 一樣：給定指定輸入，可以很快判斷是否符合；但要求得符合的解或最佳解，目前都得花上 O(2ⁿ) 以上的時間。

### 6.6 SAT 問題是 NP-Complete（Cook–Levin Theorem）

**證明思路**

- 從非確定型圖靈機下手：它會對所有可能的組合進行嘗試。
- 嚴格說不是所有組合同時嘗試，而是分成 n 條路時，機器可以「問上帝」哪條路有解，再走有解的那條繼續試——這種機制稱為**神諭（Oracle）**。
- 庫克的想法：任何一台非確定型圖靈機解決某問題，若有一條路徑可在多項式時間內找到解，就稱為 NP。
- 只要能**把該圖靈機用邏輯式描述出來**，那麼「判斷該邏輯式有沒有解」就等於「該非確定型圖靈機是否能找到答案」。

**描述圖靈機的邏輯變數**

| 變數 | 意義 |
|---|---|
| T(i, j, k) | 磁帶第 i 格在第 k 步時是否為符號 j |
| H(i, k) | 讀寫頭在第 k 步時是否在第 i 格上 |
| Q(q, k) | 第 k 步時狀態是否為 q |

- 這些變數雖然很多，但都還在**多項式範圍**內。
- 接著用邏輯式表達整台圖靈機的所有限制條件；限制條件的邏輯式數量雖比變數多得多，但也都在多項式範圍內。
- 整個系統就成為一個超大的邏輯式：只要找到滿足該邏輯式的解，就知道該非確定型圖靈機是否能找到解。

**為何這證明涵蓋所有 NP 問題**

- 圖靈機和一般機器不同，每台圖靈機都是為解決一個特定問題設計的；換言之，圖靈機就是「機器 + 程式」。
- 因此只要 SAT 能在多項式時間內解出，所有能用非確定型圖靈機在多項式時間內完成的問題，就都能在多項式時間內解出。
- 這就是庫克將「所有 NP 問題歸約（reduce）為 SAT」的方法。

### 6.7 結語

- SAT 問題可輕易轉成**整數規劃**問題，且整數規劃的解答也可在多項式時間內檢查是否符合條件，因此**整數規劃也是 NP-Complete**。
- 還有許多看似不相關的問題都被證明是 NP-Complete，證明的關鍵正是**歸約法**。
- 但直到現在，**P 是否等於 NP** 仍未被證明或否證；在可預期的未來，或許都無法被證明或否證。
- 每年都有人寫論文聲稱證明 P=NP 或 P≠NP，但每個證明都是錯的，後來的學者看到這類論文通常直接丟掉不看。

## 全書脈絡總結

| 章節 | 提出的問題 | 結果 |
|---|---|---|
| 希爾伯特的問題 | 能否形式化、機械化地自動證明所有數學定理？（完備性、一致性） | 提出希爾伯特計劃，成為後續研究的目標 |
| 哥德爾的定理 | 加入算術公理後，形式系統是否仍完備？ | 完備定理（ZFC）→ 不完備定理（ZFC + PA）：存在無法證明也無法否證的語句 |
| 丘奇的函數 | 兩個 λ-Calculus 函數是否等價？ | 不可判定：不存在能正確判定 A conv B 的遞迴函數 |
| 圖靈的機器 | 圖靈機能否判定程式是否停機？ | 不可判定：停止問題無法用圖靈機解決 |
| 喬姆斯基的語法 | 語法如何分類？與機器有何對應？ | 0～3 型文法分別對應圖靈機、線性有界圖靈機、下推自動機、有限狀態機 |
| 庫克的證明 | SAT 是否為 NP-Complete？P 是否等於 NP？ | SAT 為 NP-Complete（Cook–Levin）；P=NP 仍未解 |

**三條主要脈絡**

1. **可計算性**：希爾伯特 → 哥德爾（不完備）→ 丘奇（函數等價不可判定）→ 圖靈（停止問題不可判定）。
2. **語言與機器**：喬姆斯基階層把文法、語言、機器三者一一對應，0 型即圖靈機的能力。
3. **計算複雜度**：非確定型圖靈機 → NP → 歸約 → SAT 為 NP-Complete → P=NP 未解。

**共同手法**

- **反證法／自我指涉**：哥德爾的 Q、丘奇的 Theorem XIX、圖靈的 U(U) 都採同樣思路。
- **歸約**：把一個問題轉成另一個問題求解，是 NP-Complete 證明的關鍵工具。
- **形式化**：從公理系統、λ-Calculus 到圖靈機，都是把「推理」化為可機械操作的符號系統。
